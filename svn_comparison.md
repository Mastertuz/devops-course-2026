# Git vs SVN: ответы на вопросы

1. **Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?**
   В Git ветка — это просто указатель (40-символьный хэш) на коммит, создание нового указателя занимает миллисекунды и не копирует файлы. В SVN ветка физически реализована как копирование целой директории на сервере (`svn copy trunk branches/x`), что требует времени, места на диске и сетевого round-trip к центральному серверу.

2. **Можно ли в SVN сделать коммит без интернета? Почему?**
   Нет. SVN — централизованная система: единственная полная копия истории хранится на центральном сервере, а локально у разработчика лежит только рабочая копия текущей версии файлов. Любой коммит — это сетевая операция записи в центральный репозиторий, поэтому без соединения с сервером закоммитить изменения невозможно (можно только редактировать файлы локально).

3. **В каких сценариях SVN до сих пор может быть предпочтительнее Git?**
   - Legacy-системы в госсекторе и банках, где миграция на Git экономически нецелесообразна и связана с рисками.
   - Проекты с очень большими бинарными файлами и строгой централизованной моделью доступа/аудита, где важно, чтобы каждый чих проходил через единственный контролируемый сервер, а не расползался по локальным копиям.
   - Команды, которым нужен гранулярный контроль доступа на уровне поддиректорий (SVN это поддерживает нативно проще, чем Git).
